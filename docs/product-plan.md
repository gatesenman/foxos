# 狐狸OS（FoxOS）产品规划

> **制作一套专门给 AI 智能体使用的桌面操作系统平台。它运行在 Windows、macOS 和 Linux 上，拥有自己的虚拟桌面、应用、文件空间、命令系统和多智能体协作机制。运行时由我们自己实现，不依赖 Docker 或现成虚拟机。**

产品名称：**狐狸OS（FoxOS）**，命令前缀 `foxos`。

人可以在桌面上观察和接管；多个智能体可以通过标准命令、工具接口和图形界面，共同完成办公、设计、研发和业务任务。

狐狸OS 定位为**运行在现有操作系统之上的桌面程序**：我们自己实现桌面、应用管理和任务运行时，底层的进程、文件、网络等仍使用宿主操作系统提供的能力。

## 一、产品核心体验

用户安装狐狸OS 后，可以获得一台面向智能体的“数字电脑”。

用户输入：

> 根据这份销售数据制作分析报告、图表和演示文稿，完成后交给我审核。

系统随后：

1. 创建一个独立工作空间，读取用户授权的数据。
2. 由主管智能体拆分任务。
3. 数据智能体使用表格应用处理数据。
4. 文档智能体撰写报告。
5. 演示智能体制作幻灯片。
6. 审核智能体检查数据、图表和结论是否一致。
7. 用户在虚拟桌面查看过程和成果，必要时接管修改。

用户看到的不只是聊天窗口，还能看到：哪些智能体正在工作、它们打开了哪些应用、执行了什么命令、产生了哪些文件、哪些操作需要用户决定、工作失败后可以从哪里恢复。

## 二、产品定位与边界

| 项目 | 狐狸OS 的定位 |
|---|---|
| 产品形态 | 安装在 Windows、macOS、Linux 上的桌面程序 |
| 面向对象 | AI 智能体团队，以及需要监督智能体的人 |
| 核心界面 | 虚拟桌面、应用窗口、任务面板、命令终端 |
| 核心能力 | 应用操作、文件管理、多智能体协作、权限控制、任务恢复 |
| 内置软件 | 基于 Everything 项目逐步集成办公、创意及业务应用 |
| 自研部分 | 桌面系统、智能体运行时、命令总线、应用适配层、任务调度与权限系统 |
| 底层依赖 | 宿主系统提供的进程、文件、网络和图形能力 |

**第一版不需要从零编写操作系统内核。** 宿主系统仍负责驱动、内存管理和基础进程隔离。自研的工作空间和权限控制可以管理智能体行为，但不能默认它具备虚拟机级别的安全隔离；对不可信代码，需要结合各宿主系统的限制能力逐平台验证。

## 三、Everything 软件如何接入

[HeyPuter/everything](https://github.com/HeyPuter/everything) 是一个开源应用集合。我们把它作为**狐狸OS 的应用来源**，逐个评估、接入和测试。注意：仓库根目录为 MIT，但部分应用（包括 Spreadsheet、Presentation）声明 AGPL-3.0-only，详见[首批应用代码级评估](everything-evaluation.md)。

### 接入原则：一个应用，三种操作方式

1. **图形界面**：人可以查看和操作。
2. **标准 API / 工具接口**：智能体可以结构化调用。
3. **CLI 命令**：便于智能体、脚本和开发者使用。

```bash
foxos sheets open sales.xlsx
foxos sheets analyze sales.xlsx --sheet "2026"
foxos sheets chart create --type bar --range A1:B12
foxos sheets export report.pdf
```

这些是**拟设计的命令**，并非 Everything 当前已有的功能。底层优先直接调用应用可复用的业务逻辑；没有合适接口时开发适配层；图形界面自动操作只作为补充。

### 首批接入应用

| 优先级 | 应用 | 首批能力 |
|---|---|---|
| P0 | Documents | 创建、读取、编辑和导出文档 |
| P0 | Spreadsheet | 读取数据、修改单元格、计算、生成基础图表 |
| P0 | Presentation | 创建页面、填充内容、插入图表、导出 |

每个应用接入前建立能力清单：**已验证、部分支持、暂不支持**。

## 四、让 AI 真正熟悉软件指令

为每个应用建设可查询、可验证的**应用能力知识库**：用途、命令及参数、输入输出格式和示例、支持的文件格式、已知限制、所需权限、版本对应关系。

```text
应用：Spreadsheet
能力：创建图表
命令：foxos sheets chart create
参数：文件、数据范围、图表类型、标题
返回：图表 ID、所在工作表、执行结果
限制：第一版仅支持柱状图和折线图
```

执行流程：用户目标 → 查询应用和命令目录 → 获取参数说明与示例 → 生成结构化调用 → 权限检查 → 执行命令 → 检查结果并决定下一步。

通过标准任务集评测熟练度：能否正确打开并编辑文件、根据数据生成正确图表、发现命令失败、识别版本不兼容、避免误覆盖或越权、重复执行结果可控。每次更新应用、适配层或模型后都运行这套测试。

## 五、多智能体如何协作

| 角色 | 职责 |
|---|---|
| 主管智能体 | 理解目标、拆解任务、分配工作、汇总成果 |
| 数据智能体 | 表格处理、计算、图表与数据核验 |
| 文档智能体 | 撰写报告、整理材料 |
| 演示智能体 | 制作与调整演示文稿 |
| 设计智能体 | 处理图片和视觉素材 |
| 开发智能体 | 编写、运行和检查代码 |
| 审核智能体 | 核对事实、检查交付物和任务要求 |

每个智能体拥有身份和任务、权限、独立工作目录、共享项目目录、操作记录和资源额度。协作通过任务、消息和共享成果进行。

文件协调：读可并行；写同一文件使用锁定或版本检查；每次保存生成版本记录；冲突时提示合并或交由用户；命令有超时、取消和失败恢复。第一版：**同一文件同一时刻只允许一个写入者。**

## 六、桌面程序

核心界面：虚拟桌面、任务中心、智能体中心、应用中心、文件中心、命令终端、活动记录、人工接管。

## 七、技术架构

```text
用户
 ▼
狐狸OS 桌面程序（虚拟桌面与应用窗口 / 任务、文件和智能体管理 / 人工接管与审核）
 ▼
智能体协作层（任务拆解与调度 / 智能体通信 / 模型适配 / ACP 客户端 / 执行状态与恢复）
 ▼
狐狸OS 自研运行时（命令总线与工具接口 / 权限与策略 / 工作空间和文件版本 / 进程管理与资源限制 / 日志与审计）
 ▼
应用适配层（Documents / Spreadsheet / Presentation / 后续 Everything 应用）
 ▼
Windows / macOS / Linux 宿主系统
```

- **桌面外壳**：评估 Tauri 或 Electron；阶段 0 评估结论见评估报告第 7 节。
- **自研运行时**：Rust 或其他适合系统服务的语言；应用适配层可用 TypeScript。
- **智能体接口**：结构化工具接口和 CLI 调用同一个命令内核。
- **数据存储**：本地数据库记录任务、配置和日志，文件放在用户可管理的工作空间。

## 八、权限与安全设计

文件权限（默认只访问授权工作空间）、网络权限、命令权限（读取/创建/修改/删除/运行）、敏感操作确认、凭据安全存储、资源限制、审计记录、可恢复。要明确哪些限制是强制生效的，哪些只是应用层约束。

## 九、跨平台策略

| 平台 | 第一阶段策略 | 需要注意 |
|---|---|---|
| Windows | 首发平台 | 验证进程限制、文件权限和应用兼容性 |
| macOS | 第二阶段 | 真实 Mac 上测试签名、权限和运行体验 |
| Linux | 第二阶段 | 选择明确支持的发行版和桌面环境 |

狐狸OS 桌面程序分别运行在这些系统上，而不是在一台电脑里自行实现 Windows 或 macOS。如需智能体操作真实 Windows/macOS 环境，需单独核对授权（参见 [Apple macOS 许可示例](https://www.apple.com/legal/sla/docs/macOSVentura.pdf)、[Microsoft 容器授权说明](https://learn.microsoft.com/en-us/virtualization/windowscontainers/about/faq)）。

## 十、系统在线安装器

狐狸OS 桌面内置在线安装器，安装或之后随时可以勾选组件：

- **组件化**：每个 Everything 应用作为一个可选组件单独打包下载。评估实测首批三个应用都是独立的 Vite 项目，构建后的 `dist/` 自包含，压缩后约为：文档 18 MB、表格 5.5 MB、演示 2.1 MB。
- **组件包结构**：UI（`dist/`）+ 无头内核与 `foxos` 适配层 + `manifest.json`（版本、许可证、能力目录、所需权限、联网需求、校验和与签名）。
- **安装流程**：拉取组件索引 → 用户勾选 → 下载 → 校验签名和哈希 → 解压到应用目录 → 注册命令与能力目录 → 可回滚卸载。
- **许可展示**：AGPL 组件单独展示许可并提供对应源码入口，与 MIT 组件分开打包。
- **资源拆分**：字体、示例文件、词典拆为可选资源包，减小首装体积。
- **前置条件**：组件化前要先去掉 Puter SDK 和统计脚本，把存储和 AI 改为本地实现。

## 十一、ACP 智能体快速安装

狐狸OS 作为 [Agent Client Protocol（ACP）](https://github.com/agentclientprotocol/agent-client-protocol) 客户端，可以一键安装和运行第三方智能体：

- **来源**：读取官方 [ACP Registry](https://github.com/agentclientprotocol/registry) 的索引 `https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`。注册表只收录支持认证的智能体，每项给出 npx 包或分平台二进制及 sha256。
- **安装**：binary 类型下载、校验 sha256、解压到私有目录；npx 类型使用狐狸OS自带的 Node 并锁定版本。按握手返回的 `authMethods` 引导认证，密钥交给凭据管理。
- **运行**：每个智能体作为子进程运行在独立工作目录，通过 stdio JSON-RPC 通信；文件和终端请求映射到狐狸OS的权限与命令总线，权限请求弹到人工接管面板，全部写入审计。
- **能力提供**：通过 MCP 或命令说明，把 `foxos` 应用能力目录提供给 ACP 智能体。
- **首批候选**（2026-11-10 在注册表核实）：Gemini CLI、Codex（ACP 适配器）、Claude Agent（ACP 适配器）、Qwen Code、Kimi Code、goose、OpenCode、GitHub Copilot CLI、Codebuddy Code、GLM Agent。安装命令和许可见评估报告第 11 节。

## 十二、分阶段开发路线

以下周期仅作为小型有经验团队的初步估算。

- **阶段 0：技术验证（约 2～4 周）**：运行三个首批应用，分析复用方式；做桌面外壳打开一个应用；实现 3～5 个真实命令；让一个智能体查询命令、执行并检查结果。通过标准：智能体能够创建文件、完成修改、重新打开并验证结果。评估结论见[首批应用代码级评估](everything-evaluation.md)。
- **阶段 1：最小可用产品（约 8～12 周）**：桌面、文件中心、单智能体、命令总线、文档与表格核心命令、权限、活动记录、至少一种模型、基础评测。
- **阶段 2：多智能体协作（约 8～12 周）**：角色、子任务、消息、共享文件、写入协调、演示应用、暂停、取消、重试和接管。
- **阶段 3：跨平台与应用扩展**：macOS/Linux、应用中心与在线安装器、更多应用、ACP 智能体生态、成本控制。
- **阶段 4：团队与生态**：多用户空间、远程协作、角色模板、企业身份与审计、开发者 SDK 与应用市场。

## 十三、第一版验收指标

| 指标 | 建议目标 |
|---|---|
| 任务完成 | 固定评测集中的办公任务可以从输入完成到交付 |
| 命令可靠性 | 对已发布命令进行成功、错误参数和异常恢复测试 |
| 内容正确性 | 数据、图表与报告之间的一致性可验证 |
| 多智能体协作 | 支持至少 3 个角色参与同一任务 |
| 操作可见性 | 每个关键文件操作都能追溯到智能体和任务 |
| 文件安全 | 并发写入有冲突保护，重要修改可恢复 |
| 人工控制 | 用户能够暂停、取消、接管并继续任务 |
| 平台体验 | 在首发平台完成安装、运行、退出和重启恢复测试 |

具体百分比先通过阶段 0 测试建立基线后再确定。

## 十四、第一版产品定义

> **一台安装在 Windows 上的 AI 办公电脑，内置文档、表格和演示应用；用户交给多个智能体一个任务，它们通过统一命令协作完成，人可以随时查看、审核和接管。**
